# 目标
一个月内做出 5-10 个真人可试用的版本。后端用微信云开发，开发者只有我一人。
# 架构
- 页面一律只调用 utils/api.js，不直接碰 store。api.js 的 70 个导出函数签名保持不变。
- 把 api.js 里的 run() 改为 wx.cloud.callFunction，调用云函数 api。
- 云函数 api 按 action 路由分发，业务逻辑按域拆模块（task、quote、order、chat、notice、user、org），放在 cloudfunctions/api/modules/。
- 身份来自 cloud.getWXContext().OPENID，取代硬编码的 CURRENT_USER_ID='u1'。
- 云数据库所有集合设为客户端不可写，写操作只走云函数；权限用 auth.can 在云函数里重新校验。
- 幂等与唯一订单用唯一索引加 db.runTransaction，不再用内存字典和 let seq=2000，ID 用数据库 _id。
- utils/recommend.js 与 utils/notice.js 是纯函数，原样复制进云函数使用，现有 77 条测试必须持续全绿。
- 文件用 wx.cloud.uploadFile，保存 fileID。
- 消息用数据库 watch 实时监听，关键节点发订阅消息。
# 第一版范围
做：登录、机构与资料、发布任务、报价、接受报价、订单状态机（到验收）、私聊、文件上传、公告发布与浏览、举报、注销与退出。
不做（先隐藏入口）：公告付费置顶、费用变更、收付款申报、争议、埋点、审计日志页。
第一版不做管理端，审核和举报用云开发控制台处理。
